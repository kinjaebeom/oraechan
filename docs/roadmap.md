# 단계별 로드맵

## Phase 0 — 초기 환경 (이번 작업)

- GitHub 원격 연결과 기존 파일 확인.
- Next.js Pages Router, React, TypeScript, Tailwind, pnpm, ESLint 구성.
- 서비스명과 슬로건만 있는 최소 시작 페이지.
- README, 요구사항, 아키텍처, 디자인 시스템, 로드맵 작성.
- 파송 원본을 디자인 참고자료로 보관.
- 설치·lint·타입 검사·빌드·개발 서버 검증.

서비스 기능·대규모 UI·외부 배포는 이번 범위에 포함하지 않습니다.

## Phase 1 — 핵심 MVP (미구현)

첫 작업은 **파송 UI 기반 오래찬 홈 레이아웃과 공통 스타일 구현**입니다. 브랜드명과 콘텐츠를 오래찬으로 정리하고 데스크톱/모바일 구조를 확정합니다.

이후 감정/메시지 선택 → 검증된 곡 데이터와 순수 추천 함수 → 검색/필터 탐색 → 고유 URL 상세와 공식 영상 → 즐겨찾기/공유 순으로 연결합니다. 접근성은 각 기능의 기본 완료 조건에 포함합니다. 추천의 가중치·동점·일치 없음 정책과 콘텐츠 출처를 먼저 확정합니다.

완료 기준: 로그인 없이 선택부터 추천·상세·감상·저장·공유까지 이어지고, 빈 결과와 오류 상황에서도 사용자가 다음 행동을 할 수 있습니다.

## Phase 2 — 다국어 및 접근성 (미구현)

Pages Router에 적합한 한국어/영어 구성, 직접 쓴 소개글 번역, 키보드/스크린리더 점검, 대비와 모바일 반응형 개선. 노래 가사 번역은 제외합니다.

## Phase 3 — 품질 및 생산성 (미구현)

Storybook, Vitest, React Testing Library, 자동 접근성 검사, GitHub Actions, Lighthouse. 추천 경계 사례와 사용자 흐름을 우선 검증하며 필요한 도구만 도입합니다. 실제 썸네일 도입에 맞춰 이미지 최적화를 적용합니다.

## Phase 4 — 확장 기술 (미구현)

카드/리스트 기능 플래그와 이벤트 POC, 필요성이 있는 SSR POC, 공통 UI 패키지 필요 시 pnpm Workspaces/Turborepo. 트래픽 없이 통계적 A/B 성과를 주장하지 않습니다. Module Federation은 독립 배포 필요가 생기기 전에는 도입하지 않습니다.

## Phase 5 — 운영 및 확장 (미구현)

Vercel 실제 배포 전 콘텐츠·영상·접근성·모바일·오류 처리 점검. 사용자 피드백, 곡 확충, 외부 추천 폼, 운영 개선. 동기화나 공개 댓글은 별도 저장 서비스 필요성을 판단한 뒤 별도 범위로 진행합니다. 수익화는 장기 검토 사항입니다.
